# CI/CD implementation plan

Goal: GitHub Actions verifies pull requests and deploys tested staging/main pushes to Vercel Preview/Production.

Agreed scope: GitHub Actions + Vercel; staging and production use separate Neon endpoints. Work in the current checkout because the app's database implementation is not committed yet and is required by this workflow. Preserve existing work.

- [ ] Add a single workflow: test/build with disposable Postgres 18 and Node 24, then environment-scoped deployment on branch pushes only.
- [ ] Make existing database commands accept injected environment variables without requiring a local secrets file. Validate the intended Neon endpoint before migrations; test missing, malformed, mismatched, and production-in-staging configuration.
- [ ] Document GitHub environments, required variables/secrets, Vercel environment mapping, staging branch provisioning, migration/rollback limits, and activation steps.
- [ ] Validate workflow syntax, run tests (including disposable local Postgres), typecheck/build, and request focused review.

Deployment gate: environment variables must be configured before release. Pull requests never receive deployment credentials. Do not run integration tests against either live Neon branch. Do not publish or push the user's uncommitted application changes.
